# Mini App «Штурман»

Автономная статическая Mini App внутри `index.html`. Сборка, npm-пакеты, шрифты, CDN и отдельный backend не нужны. Единственный внешний скрипт — официальный `https://telegram.org/js/telegram-web-app.js`.

## Возможности

- **Дашборд:** локальные счётчики MIND/WORK/VOICE/BODY, открытые локальные задачи и просадка ресурса «вход минус выход» за текущий локальный день.
- **Заметки:** добавление, отправка одной записи и список локальных записей.
- **Ресурс:** голова, тело и настрой на ползунках 1–5; входной и выходной замеры сохраняются отдельно.
- **Задачи:** добавление, необязательный дедлайн с обязательной причиной, выполнение и перенос с обязательной причиной.
- **Отправить всё:** один пакет ожидающих заметок, замеров и изменений задач; **«Повторить все пакеты»** повторно передаёт все сохранённые pending-пакеты с прежними `clientId`.

Приложение не читает состояние бота. Поэтому дашборд и список задач — именно локальный снимок этого устройства. Изменения, сделанные командами `/done` или `/reschedule` вне Mini App, автоматически в интерфейс не загружаются.

## Локальный просмотр интерфейса

Можно открыть `index.html` напрямую. Для просмотра через локальный HTTP-сервер без установки зависимостей, если установлен Python:

```sh
python -m http.server 8080 --directory miniapp
```

Затем открыть `http://localhost:8080`. Вне Telegram отображается локальный режим: редактирование доступно, отправка объяснено отключена. Для запуска из Telegram нужен публичный HTTPS, а не `localhost` или `file://`.

## Размещение и подключение

1. Разместите содержимое каталога `miniapp/` на любом статическом HTTPS-хостинге. Точка входа — `index.html`; серверный код и переменные бота туда не входят.
2. В локальном `.env` бота задайте владелец файла:

   ```dotenv
   MINIAPP_URL=https://<ваш-хост>/index.html
   ```

   Не вписывайте токен бота или другие секреты в HTML и публичный репозиторий.
3. Перезапустите существующий бот-процесс обычной командой `npm start` из корня проекта.
4. В **личном чате владельца** вызовите `/app` и нажмите появившуюся reply-кнопку **«Открыть Mini App»**.

Важно: используется именно Keyboard button, а не inline-кнопка. По ограничению Telegram `Telegram.WebApp.sendData()` предназначен для Mini App, запущенного через Keyboard button. При таком запуске бот получает service message `web_app_data`. Отдельная настройка меню BotFather для команды `/app` не требуется.

Если `MINIAPP_URL` не задан, `/app` не показывает неработающую кнопку, а объясняет настройку. Принимается только HTTPS URL без учётных данных в адресе.

## Сохранность и отправка

- Все изменения сразу записываются в `localStorage` под ключом `life-rpg-miniapp-v1` и восстанавливаются после перезагрузки.
- Перед `sendData()` сам сериализованный пакет и его стабильный `clientId` сохраняются в `pendingPackages`: Telegram может закрыть Mini App сразу после вызова.
- Если SDK или Telegram-контекст недоступны, отправка не выполняется и показывается понятное сообщение. Локальные данные остаются на месте.
- `sendData()` не является подтверждением записи ботом. Результат — отдельный ответ бота в чате; Mini App этот ответ не получает и не показывает выдуманный статус подтверждения.
- Вызов `sendData()` **не снимает `pending`** и не удаляет пакет: это не подтверждение записи. После перезагрузки кнопка **«Повторить все пакеты»** отправляет сохранённые строки повторно с теми же `clientId`; серверная дедупликация предотвращает дубли. Повтор тех же данных из общей кнопки или карточки также переиспользует уже сохранённый пакет, а не создаёт новый `clientId`.
- Лимит Telegram — 4096 байт UTF-8 на пакет. При превышении пакет не отправляется; отправьте заметки или задачи по одной.
- Статические файлы можно размещать публично: они не содержат пользовательских записей. Данные находятся в хранилище конкретного браузера/устройства.

## Формат пакета

Актуальная версия протокола:

```json
{
  "version": 1,
  "clientId": "package-…",
  "notes": [{ "id": "note-…", "text": "Текст" }],
  "resources": [
    { "date": "2026-10-26", "phase": "entry", "head": 4, "body": 3, "mood": 4 }
  ],
  "tasks": [
    {
      "id": "task-…",
      "text": "Задача",
      "date": "2026-10-26",
      "due": "2026-10-30",
      "reason": "Причина срока",
      "done": false,
      "reschedules": []
    }
  ]
}
```

`phase` принимает `entry` или `exit`. У закрытой задачи передаётся `doneDate`; `due` — текущий срок после всех переносов, а записи истории содержат `from`, `to`, `reason` и `at`. Бот проверяет весь пакет через Zod до записи.

## Что делает бот

`src/webapp.ts` ограничивает размер и проверяет JSON, даты, слайдеры 1–5, обязательные причины и цепочку переносов. Заметки записываются в `Inbox`, замеры — в `resourceMeasures`, задачи — в `tasks` существующего `StateStorage`.

Повтор одного `web_app_data` не создаёт дублей. Для нескольких заметок одного update используется стабильный `sourceId`; задачи имеют стабильный ID, замеры уникальны по дате и фазе, переносы дедуплицируются по истории. После успешного применения в `state.json` сохраняется fingerprint `clientId`: повтор того же пакета не меняет состояние повторно, а тот же `clientId` с другим содержимым отклоняется. Квитанция ставится только в конце, поэтому пакет можно безопасно повторить после частичного сбоя записи.

Существующее ограничение безопасности сохраняется: middleware бота обрабатывает данные только от `TELEGRAM_OWNER_ID` и только в личном чате.
